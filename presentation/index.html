05 / CONCURRENCY并发

并发发生在连接与后台任务，写入仍由 Executor 串行化

项目封装的是第三方 ants 协程池；pool.Submit() 负责复用任务执行单元，不是自研完整协程池。

ServerAccept TCP→提交连接处理
ants PoolHandler.Handle()→Parser.parse()
ChannelDroplet→Command
Executorrun() / KVStore→ Reply
AOFbuffer→后台 Writer
复用与上限

ants.NewPool(50000) 配置容量上限；不是宣称实际同时运行 5 万任务。

分工

Parser 在独立提交的任务中解析；Executor 通过命令 Channel 接收；AOF Writer 后台消费缓冲。

权衡

连接处理可并发，但同一执行器的命令执行集中排队；慢命令会占住该循环。

源码：server/server.go · protocol/parser.go · database/executor.go · persist/aof.go · lib/pool/pool.go
06 / PERSISTENCE持久化

AOF 把写命令排队记录，启动时按原协议重放

写入 / FORWARD

命令提交与磁盘同步分离

Sync 策略always 每次写入后everysec 约每秒一次no 运行中不主动同步
恢复 / REPLAY

历史命令重新进入执行链

Reloader() 读取 AOF↓Parser.ParseStream()↓Handler.handle() / DBTrigger↓DBExecutor → KVStore↓内存状态重建
LoadingPattern

恢复上下文带标记，PersistCmd() 遇到该标记直接返回，避免重放时再次写入 AOF。

边界　写入 AOF Channel 只代表任务已提交；是否落盘取决于 Writer 与 Sync 策略。
